# Koordinatorstvo HR — как устроен репозиторий

Документ для быстрой ориентации в кодовой базе: назначение системы, компоненты, данные и типичные сценарии работы.

## Назначение

Веб-приложение для **отбора обучающих координаторов** («Координаторство HR»): координаторы проверяют **анкеты** и **домашние задания** по рубрикам, заполняют **бланки собеседований**, администратор **распределяет работу** по факультетам, задаёт **слоты собесов и ёмкость**, кандидаты **записываются на собес** по студенческому билету (публичная страница). Источник правды по входным данным — **Google Sheets**; оценки частично **выгружаются обратно в таблицу**. Есть опциональная интеграция с **Telegram** (карточки «легендарные ответы» в чаты по факультетам).

## Стек и развёртывание

| Слой | Технологии |
|------|------------|
| Backend | Python 3.12, FastAPI, SQLAlchemy 2, SQLite |
| Frontend | Vue 3, Vite, Axios; в Docker — статика + nginx |
| Инфра | `docker-compose`: backend, frontend (порт хоста **8090→80**), **Redis** |
| Внешние сервисы | Google Sheets (service account + `credentials.json`), опционально Telegram Bot (aiogram polling) |

- **Локальная разработка фронта**: `vite` проксирует `/api` → `http://localhost:8000` без префикса (см. `frontend/vite.config.js`).
- **Docker**: nginx шлёт `/api/` на `backend:8000/` (см. `frontend/nginx.conf`). SQLite и Redis данные в именованных volumes.

Переменные окружения бэкенда описаны в `backend/.env.example`: `SPREADSHEET_ID`, `SECRET_KEY`, `GOOGLE_CREDENTIALS_PATH`, `REDIS_*`, `TELEGRAM_BOT_TOKEN`.

## Google Sheets — три листа

Ключи в коде и имена листов (см. `backend/app/sheets.py`):

| Ключ (`sheet`) | Имя листа в таблице | Роль |
|----------------|---------------------|------|
| `anketa` | Анкеты | анкеты кандидатов |
| `homework` | Домашка | домашние работы |
| `interview` | Собес | список на собеседование |

Для анкеты и домашки ответы читаются из колонок **C–AL**; колонки оценок рецензента задаются отдельно (например AN для анкеты, H для домашки). Лист **Собес** пока **не получает** запись оценок из `sync` — в коде явно отмечено как будущее расширение.

## Модели данных (SQLite)

Файл `backend/app/models.py`:

- **User** — email, имя, пароль (hash), роль (`admin` | `coordinator`), список **факультетов** (`faculties` JSON).
- **SheetRow** — кэш строки из Sheets: `sheet`, `row_number`, `data` (JSON).
- **Assignment** — кто проверяет какую строку листа «анкета» или «домашка» (одна строка — один проверяющий).
- **Review** — оценки/комментарии рецензента по строке листа; флаг `synced_to_sheets` для инкрементальной выгрузки в Google Sheets.
- **Availability** — слоты «могу» для координатора (`slot_date`, `slot_hour`); отсутствие строки = не могу.
- **SlotCapacity** — администратор задаёт **ёмкость** слота (сколько собесов в этот час).
- **InterviewAssignment** — на строку листа «Собес» два проверяющих + опционально выбранный слот (`slot_date`, `slot_hour`, `booked_at`).
- **TelegramChat** — привязка чатов к списку факультетов для рассылки.

При старте приложения: `create_all`, лёгкие **ALTER** миграции в `main.py`, **сид пользователей** (админ и список координаторов — зашиты в `main.py`; пароли не дублировать в документации).

## API-роутеры (префиксы)

| Префикс | Файл | Назначение |
|---------|------|------------|
| `/auth` | `routers/auth.py` | JWT логин |
| `/users` | `routers/users.py` | пользователи (в т.ч. факультеты для координаторов) |
| `/sheets` | `routers/sheets.py` | админ: полная загрузка листов в БД; пользователь: просмотр строк с фильтром по назначениям |
| `/reviews` | `routers/reviews.py` | критерии, автосохранение черновиков в **Redis**, финальное сохранение в SQLite |
| `/admin` | `routers/admin_ops.py` | распределение анкет/домашек, статистика, полная выгрузка review в Sheets |
| `/availability` | `routers/availability.py` | своя занятость; админ — обзор и ёмкости слотов |
| `/telegram` | `routers/telegram.py` | чаты, отправка карточек; polling бота при наличии токена |
| `/interview` | `routers/interview.py` | форма собеса, список «мои собесы», заметки (Redis + сохранение), админ — массовое назначение пар проверяющих |
| `/booking` | `routers/booking.py` | **публично**: поиск по студ. билету, слоты, бронь без авторизации |

Корневой эндпоинт: `GET /health`.

## Ключевые сценарии

### 1. Загрузка данных из Sheets

Админ вызывает `POST /sheets/load` — перечитываются все три листа, для каждого ключа строки **полностью заменяются** в `SheetRow` (не инкрементально).

### 2. Распределение анкет

`POST /admin/distribute` с телом `{ "sheet": "anketa" }`: по автоматически найденному столбцу факультета строки делятся между координаторами, у которых этот факультет в `faculties`, с балансировкой нагрузки.

### 3. Домашки — фон и ручной синк

Фоновый поток в `main.py` каждые **5 минут** вызывает `sync_homework_and_distribute`: подтягивает **новые** строки домашки из Sheets (без удаления старых из БД), затем назначает нераспределённые строки координаторам по факультету из анкеты (матч по нормализованному студ. билету). Ручной запуск: `POST /admin/homework/sync`.

### 4. Проверка анкеты / домашки

Координатор видит в UI только назначенные строки (если для листа уже есть записи в `Assignment`). Оценки сохраняются в `Review`; черновики при наличии Redis — в ключах вида `autosave:{sheet}:{row}:{user}`.

### 5. Синхронизация оценок → Google Sheets

Фоновый поток каждые **3 минуты** вызывает `do_sync()` (`backend/app/sync.py`): выбираются `Review` с `synced_to_sheets=False`, пакетно пишутся в Sheets; пометка `synced=True` делается только если `saved_at` **не изменился** (оптимистичная блокировка — параллельное сохранение не потеряется). Админ может запустить полную выгрузку через эндпоинт в `admin_ops` (`do_full_export`), включая чистку наследия строк `"None"` в ячейках.

### 6. Собеседования

Структура бланка — `backend/app/interview_form.py`. Назначение двух проверяющих на строку «Собес» — через админский интерфейс/API interview. Заметки во время собеса могут жить в Redis и затем сохраняться в БД.

### 7. Запись кандидата на слот (`/booking`)

Публичный UI (`/booking` во Vue без авторизации). Кандидат вводит студ. билет → бэкенд ищет строку в `SheetRow` для `interview`, факультет берётся из кэша анкет. Слоты строятся из `SlotCapacity`, `Availability`, уже занятых `InterviewAssignment` и правила «нужно ≥2 свободных координатора в час». Приоритет «recommended» — когда есть два координатора с факультетом кандидата; иначе слот помечается как «other».

### 8. Занятость координаторов

Период слотов **жёстко задан** в `availability.py`: **9–23 мая 2026**, часы **9–21**. Админ задаёт ёмкость по слотам; координаторы отмечают, когда могут прийти.

## Frontend (маршруты)

Файл `frontend/src/router/index.js`:

- `/login` — гость  
- `/booking` — публичная запись  
- `/`, `/applicants`, `/applicants/:sheet/:rowNumber` — дашборд и проверка заявок  
- `/availability` — своя занятость  
- `/interviews`, `/interviews/:rowNumber` — собеседования  
- `/admin`, `/admin/assignments`, `/admin/availability`, `/admin/settings`, `/admin/interview` — только админ  

Токен JWT хранится в `localStorage`; Axios подставляет `Authorization` и при 401 редиректит на логин (`frontend/src/api/index.js`).

## Зависимости и CORS

Backend: см. `backend/requirements.txt` (FastAPI, gspread, redis, aiogram, Pillow и др.). CORS в `main.py` разрешён для `localhost:5173` и `localhost` (для dev).
